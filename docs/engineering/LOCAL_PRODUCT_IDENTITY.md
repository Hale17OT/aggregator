# RNM-F04/F05 local identity and listening

Migrations 0001–0005 remain unchanged. 0006 adds browser-bound captured-mail challenges and database rate limits; 0007 adds strict playback preferences and private queue/progress tables. Existing expired/legacy identities are not upgraded to verified mail ownership. New records have `captured-mail` / `local-demo` assurance, NULL email verification/MFA, and only the reader role. Staff accounts cannot enroll through this flow.

The request accepts normalized ASCII example.test addresses only (trim/lowercase; no dot/plus transformations). Request responses are generic. A 256-bit random one-use link secret is hashed in PostgreSQL, expires in 15 minutes, and binds a separately random HttpOnly pre-auth cookie. A same-origin CSRF header is required on both request and confirmation. The credential is in the link fragment; the confirmation page reads and removes it immediately, retains it in memory only, and requires an explicit POST. GET previews neither redeem nor create sessions. Use the browser which requested the link; a new browser must request its own link.

Request limits (5/address and 60 globally per 15 minutes), verification limits (20/browser binding and 120 globally), challenge consumption, reader creation, preferences and session issuance use the database. Redemption is atomic and single-use across API processes. Incorrect links return no account details. Auth requests use one checked-out connection; ambiguous COMMIT failures discard it and are never reported as verified rollback. Existing 30-minute idle / 12-hour absolute session limits, current-account version checks, synchronizer CSRF and exact Origin checks remain. Mail delivery failure reports unavailable; it never returns a link in the application API.

Mailpit 1.31.4 is a verified MIT workspace binary. Its SMTP and UI bind only 127.0.0.1. The supervisor removes MP_* configuration, supplies no relay/forwarding settings, disables update checks, and blocks remote CSS/fonts. Mail and retained database contents in ignored .cache are private local demo data, not public review artifacts. Local trust-auth PostgreSQL assumes a trusted workstation; it is not a production deployment profile.

Listening queues use an expected revision and at most 50 unique ready programme IDs. Progress uses an expected revision, rendition key, measured duration, clamped nonnegative position and server timestamps. Per-account transaction locks and RLS protect every read/update/delete; runtime roles remain non-owner. Public projections are checked again when listing saved articles and listening items. History can be disabled; clear-history deletes rows. The client throttles progress to 12 seconds plus pause/seek and does not upload an already-playing guest programme on sign-in. Guest queues require an explicit import choice.

Prepared voices are the supported voice choice. Speed and one/two presenters affect playback. Both clip treatments currently occur in the prepared Newsroom sequence; selecting a treatment does not generate a distinct rendition, and the interface states this fallback. External email, OIDC, real mailbox assurance and staff MFA remain unimplemented and unauthorized.
